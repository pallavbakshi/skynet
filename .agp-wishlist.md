## Genuinely Missing — Needs Building

### 1. Structured Output Contracts [Priority: HIGH — agreed first build]
**Pain**: Reviewer writes findings to a markdown file that the orchestrator must parse.
No way to request JSON output conforming to a schema. Misparsing leads to false approvals.

**Proposal**: Add `output_contract` to SendMessageRequest with `format: "json"` and `json_schema: dict`.
Include contract in `/runs/claim`. Validate final result artifact against schema before completing.
On validation failure, call `/runs/{id}/fail` with actionable error. Store both raw and validated output.

**Status**: ☐ Not started

### 2. Multi-Turn Conversations [Priority: HIGH — agreed second build]
**Pain**: Every `agp send` is a cold start. No conversation_id, parent_message_id, or reply-to.
The orchestrator must re-explain full context each time. Review cycles take 5 rounds instead of 2.

**Proposal**: Add `conversation_id` and `reply_to_message_id` to Message model.
New `agp reply <job_id> "text"` CLI command. Include bounded conversation context in claim payload.

**Status**: ☐ Not started

### 3. File/Attachment Passing in Messages [Priority: HIGH — agreed third build]
**Pain**: Cannot attach files when sending messages. Must inline entire diffs in prompts.
Artifact upload is text-only JSON, no multipart. Agents can only read workspace files.

**Proposal**: Add `attachments` field to SendMessagePayload. CLI resolves paths, uploads via
`/artifacts/upload`, sends with artifact references. Adapters prepend attachment manifest to prompt.

**Status**: ☐ Not started

### 4. Per-Job Timeout Hints [Priority: MEDIUM]
**Pain**: Long-running tasks (3-min integration tests) timeout at CLI level but the job keeps
running. No way to set "this task should take at most N seconds" at the job level.

**Proposal**: Add `timeout_seconds` to Job model and `deadline_at` derived field.
CP checks deadline on heartbeat/progress. Cooperative enforcement via existing interrupt path.

**Status**: ☐ Not started

### 5. Built-in Review Workflow [Priority: LOW]
**Pain**: Manual orchestration of review loops.

**Proposal**: CLI-only `agp review <job_id> --reviewer <agent_id> --max-rounds 5`.
No server-side workflow engine until items 1-3 exist.

**Status**: ☐ Not started

## Agent Perspectives

### codex-dev (builder)
- All 5 items are genuinely needed — confirmed by code tracing
- Wanted multi-turn conversations first (highest impact, foundational for others)
- Concrete first slice: conversation_id on Message/Job, reply CLI command, bounded context in claim
- Key concern: context growth needs a cap; keep v1 simple (bounded array, not full transcript replay)
- File passing v1 should be text-only; don't open the binary/multipart problem yet
- Review workflow should wait — depends on conversations + structured output

### codex-reviewer (QA)
- Wanted structured output contracts first (most improves review correctness)
- Key insight: "build stricter before more complex" — structured output makes later features safer
- Concerns about hidden state risk in conversations (stale context contamination)
- Insisted on: explicit conversation context (not magical), inspectable by QA
- Insisted on: structured validation must store both raw and validated output, never discard raw
- Review workflow is premature until contracts + conversations exist

### Claude Code (orchestrator)
- Agree with reviewer: structured output first, then conversations
- Reason: structured output is smaller scope, more isolated, and makes the review loop I actually run
  (orchestrator parses reviewer output, sends to dev) immediately more reliable
- Multi-turn conversations are the bigger productivity win long-term but depend on more moving parts
- The real win is: once structured output exists, the `agp review` loop can be implemented as a
  client-side script without needing server-side state machine
